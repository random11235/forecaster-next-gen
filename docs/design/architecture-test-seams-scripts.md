# Architecture: Script tests

Part of the test seams; see [`architecture-test-seams.md`](architecture-test-seams.md), whose index is [`architecture.md`](architecture.md).

`test/scripts/restartLocal.test.ts` is not a forecasting seam either: it runs `scripts/restartLocal.sh`, which the restart workflow (`.github/workflows/restart-local.yml`) calls after each merge to `main`, against the same built app on a spare `PORT`, with a stand-in `open` on `PATH`, writing the app's launch agent to its own directory (`LAUNCH_AGENTS_DIR`). It checks that the script stops what held the port and leaves the app serving after it exits, run by launchd as a launch agent in the user's login session, where it can read the keychain (#290), fails with the app's output when the app doesn't come up, and opens a tab only when no page reconnects to `/live`. The script runs only on macOS, as the runner does, so the test skips on CI's Linux and runs in the pre-push hook. The workflow and the runner setup wizard (`scripts/setupRunner.sh`) are checked by a real merge, not by tests. `test/scripts/changeFiles.test.ts` tests the change-file check `check:static` runs on a branch (`changeFileProblems` in `scripts/changeFiles.ts`), on a branch's files at its base and head, the bump a new migration step or demo screenshot needs among them (`scripts/bumpFloors.ts`, tested through the check, with the MIGRATIONS source built by `test/migrationsSource.ts`, which `test/storage/storedValues.test.ts` shares), and where a release's section goes in `CHANGELOG.md`. `test/scripts/mergeBase.test.ts` tests how those checks find the commit they diff from (`scripts/mergeBase.ts`): a base's merge-base with HEAD, and a base the repo doesn't have failing with the caller's hint for getting it. `test/scripts/moduleDepth.test.ts` tests the shallowest modules CI's summary lists (`scripts/moduleDepth.ts`): a module's `index.ts` or each file at its root, its exported functions and types and the code lines it hides, then the report run over the real `src/`. `test/scripts/ownFolderCoverage.test.ts` tests how each module's coverage by its own test folder is judged against its thresholds (`scripts/ownFolderCoverage.ts`): a folder's figures read from Vitest's coverage summary, the report and each drop, and that each folder of `src/` has thresholds or is listed as having no test folder of its own; CI runs the measuring itself. `test/scripts/sourceFiles.test.ts` tests how the scans find and resolve imports (`scripts/sourceFiles.ts`). The release ([`architecture.md`](architecture.md#release)), `scripts/release.ts`, is tested in git repos of its own, never the real repo's, with the tags, branches and merges each case needs (`test/scripts/releaseRepo.ts`): `test/scripts/release.test.ts` the version and section the change files make and which change files a release takes, with each one's PR; `test/scripts/release.run.test.ts` runs the script as the release job does, from a clone of a bare repo standing in for GitHub: merges released in turn and in flight together, a change file a red run left, a docs-only merge, an app change with no change file, and a push refused, then retried or given up. The job itself is checked by a real merge. `test/scripts/lintBoundaries.test.ts` runs the module-boundary check (`scripts/lintBoundaries.ts`) over the real repo, which passes, and over stand-in repos of its own: a deep import into another module's subfolder, from a module or a test, an `import type` among them, and a cycle each fail, an entry point passes, and a run that cruises no modules fails; `test/scripts/lintBoundaries.layering.test.ts` shows each layering rule between modules failing on an import that breaks it, a side-effect import and a dynamic `import()` among them, and passing what it allows. Both share the stand-in repos of `test/scripts/boundariesRepo.ts`. `test/scripts/prePush.test.ts` runs the pre-push hook (`.husky/pre-push`) in a stand-in clone whose `npm run check` passes or fails, and checks that a failing one refuses the push with its output shown.

`test/scripts/mutationTargets.test.ts` tests `scripts/mutationTargets.ts`, which turns a branch's `git diff -U0` into the line ranges a mutation run mutates (`npm run test:mutation`), with diffs written in git's format as the seam: changed and new files, renames, lines only removed, paths git pads or quotes, and the files left out.

`test/scripts/mutationSummary.test.ts` tests `scripts/mutationSummary.ts`, which turns Stryker's JSON report and the run's targets into CI's job summary of the run, with reports written in Stryker's schema as the seam: lines mutated, ranges and new files alike, mutants by status, survivors (survived or not covered) per line mutated, and each survivor on its own table row. A real pull request's run checks that Stryker writes the report and that CI shows it.

`test/scripts/factoryAgent.test.ts` tests `scripts/factoryAgent.ts`, the Claude Code agent the factory runs in Sandcastle, with the command it builds as the seam: the prompt as Claude Code's argument, after `--`, so a slash command expands; any prompt (quotes, `$()`, backticks, newlines, `$&`, a leading `-`) reaching a stand-in `claude` unchanged through `sh -c`, as Sandcastle runs it; a prompt too long for a command line, or holding a NUL byte, refused; the `--max-budget-usd` cap; `stdinAgent()`, the smoke test's control, which keeps Sandcastle's stdin prompt with the same cap and env; the sandbox's env holding only `CLAUDE_CODE_OAUTH_TOKEN`; and the throw if `claudeCode()` stops ending its command in `-p -`, which only a Sandcastle bump past the pinned 0.14.0 would do.

`test/scripts/factoryTicket.test.ts` tests `scripts/factoryTicket.ts`, the prompt the factory gives its agent for a ticket, with the ticket and its comments as GitHub's REST API gives them as the seam: `/implement <n>`, then the ticket in a `<ticket>` block, which tells `/implement` the factory runs it; the owner's and collaborators' comments kept, in order, under their authors, and everyone else's left out; the title and body of a ticket someone else opened left out, saying so; and the factory's own comments, which carry its mark, left out, with the workflow marking its comments with that same mark. `test/scripts/factoryPullRequest.test.ts` tests `scripts/factoryPullRequest.ts`, the body of the PR the factory opens, with the agent's reply as the seam: the last `<pr-body>` block it holds, or a stand-in in `/pr`'s sections if there is none, cut to fit GitHub's limit, then the line closing the ticket and the run link. `test/scripts/factoryOutcome.test.ts` tests `scripts/factoryOutcome.ts`, how a build ended, with what Sandcastle's `run()` returned or threw and Claude Code's stream-json as the seam: built, no commits, a dirty tree, the budget's stop (which wins over commits), Sandcastle's idle timeout or another error, each out of the FiberFailure its `run()` rethrows, built with Sandcastle's own bundled effect and errors, each but built with the reason the ticket is parked for. The factory itself (`.github/workflows/factory.yml`, which runs `scripts/factoryBuild.ts`) needs a GitHub runner, bwrap and the OAuth token, so is checked by real runs on throwaway tickets, recorded in each ticket's PR.

`test/scripts/smokeVerdict.test.ts` tests `scripts/smokeVerdict.ts`, which turns what the factory's smoke test saw into its checks, with Claude Code's stream-json, the agent's `<smoke-report>` and what changed on the host as the seam: the slash command expanded only if the agent's first move, before any tool, was to say the skill's word; no GitHub token in the env of Claude Code or of its tools; no `.sandcastle/.env`; no commit; writes outside the tree fail, except into the git dir's HEAD, refs and objects, which are noted; the stdin control, whose writes that reach the host are judged by the same rules; and the budget cap stopped its run, read from Claude Code's result. The smoke test itself (`scripts/factorySmoke.ts`, run by `.github/workflows/factory-smoke.yml`) needs a GitHub runner, bwrap and the OAuth token, so it runs only when dispatched by hand, never in CI.

`test/scripts/smokeHost.test.ts` tests `scripts/smokeHost.ts`, which decides whether a write the smoke test had the agent try reached the host and how to undo it, with what was at the target and its directory before the run and after as the seam: a file unchanged, changed, new, or swapped for a symlink or something else, which restoring removes, putting back the file that was there; a directory moved, removed, unreadable, or swapped for a file (or a file made where a missing one would be), which counts as a change and is left as it is, with the reason to warn of; a directory that was already something other than a directory, and still is, which doesn't; a directory's path that was something else becoming a directory where it should be, which counts as a change, and of which restoring removes only the file, warning of the directory, or becoming one elsewhere, which is left as it is, warned of with where it now resolves rather than where it should; one that couldn't be read becoming a directory, which counts as a change and is left as it is, file and all, warned of as such; and a directory the agent made where one was missing, which counts as a change even empty, and of which restoring removes only the file, leaving the directory and warning of it, or one it made that resolves elsewhere, which is left as it is, warned of with where it now resolves rather than where it should. `scripts/factorySmoke.ts` does the I/O: what it sees on the host, and the removing and warning. It also stops before any run if a target is a symlink, or neither a file nor missing, since writes to it would go unseen, and fails the smoke test if a restore fails.
