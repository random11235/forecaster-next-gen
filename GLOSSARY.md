# Glossary

**Team facts**: a team's facts as its workflow reads them. Each ticket's started, done and cancelled times come from its status history under the EM's status mapping, and so do the commits that still stand (see **Pull-back**). Forecasts only ever see team facts, never the facts as the connector stored them.

**Baseline**: the number of children an epic had when the EM committed it; cancelled children don't count. The epic's growth is measured from it. An uncommitted epic has only a provisional baseline, its current count. Stored as `child_count_at_commit`.

**Commit** (of an epic): the EM's statement, made in the tool after kickoff, that an epic's scope is understood. It records the epic's baseline. A team that labels consistently can commit instead by applying the workflow's commit label: the baseline is then the child count when the label was applied. Label commits are derived from label history on each read, never stored, so setting the commit label commits each epic that already carries it, as of when it was applied. Removing the label doesn't uncommit the epic: only a pull-back does. The commit that stands is the first made since the last pull-back: while one stands, applying the label again doesn't replace it. Not the milestone's committed date, which is the date the milestone is promised for.

**Pull-back**: an epic moving from a status mapped to started back to one mapped to not started. A move into a status of the blocked rule is not a pull-back: a blocked epic keeps its commit. Leaving a blocked status is read against the status before it, so started, blocked, then not started is a pull-back. A pull-back after a commit resets it: the epic is uncommitted until it is committed again, in the tool or by applying the commit label. It is derived from status history under the team's workflow on each read, never stored.
